# Simplifier les parcours, sans ajouter une couche de navigation

Capture du site publié le **15 novembre 2026**, en **1920 × 1080** et **390 × 844**, sur le chantier fictif demandé. [Galerie des écrans réels](index.html), [mesures et méthode](mesures.json). Aucun contenu saisi, aucune application modifiée, révisions natives inchangées, zéro erreur JavaScript observée.

Le problème principal est la **superposition de plusieurs interfaces pour le même travail**. La correction attendue porte sur les choix présentés et la structure ; une nouvelle palette ne suffit pas. Mode **Operate**, travail cible : retrouver le dossier, lire ou écrire, suivre une action, retrouver un document ou un courriel. Le brief utilisateur et `PRODUCT.md`/`DESIGN.md` fournissent ce contexte ; aucune enquête supplémentaire n’est supposée avoir été menée.

## Ce qui doit rester intact

Le moteur AFFiNE/BlockSuite natif, les mêmes lignes en Tableau/Kanban, la saisie de notes et blocs, les courriels et pièces originales disponibles, les preuves cliquables, les versions et décisions humaines. Retirer les statuts génériques décoratifs de l’en-tête ne doit pas retirer les états réels d’exécution d’une tâche ou masquer une proposition non validée.

## Vérifications et limites

- Dix captures de contenu plus une capture du rail mobile ; images originales non retouchées et sans recadrage masquant des contrôles.
- Les deux tailles ne présentent pas de débordement horizontal du document dans les mesures collectées. Ce n’est pas un audit RGAA complet ; lecteur d’écran, RTL, zoom 200 %, contenus extrêmes et états d’erreur n’ont pas été revérifiés ici.
- Les accès privés ont été lus en mémoire sans être affichés. Le navigateur et son contexte sont isolés, sans CUA ni compte utilisateur existant.
- Le POST technique qui ouvre la page existante a été résolu par ses vraies métadonnées récupérées en GET. Les autres mutations API étaient interdites. **Zéro mutation bloquée n’a été déclenchée** pendant les captures ; les révisions avant/après sont identiques.
- Skills : `impeccable context` exécuté avec succès, playbook `distill`, règles `better-layout` et `better-writing`. Il s’agit d’un audit de réduction fondé sur les écrans, pas d’un score esthétique ni d’une critique complète à deux évaluateurs. Aucun code applicatif ou paramètre de déploiement modifié.

Les six points sont des problèmes d’organisation et de compréhension, sans nouveau blocage fonctionnel de sévérité HIGH démontré dans cette passe. **Approve pour la fidélité du dossier de preuves uniquement** ; les réductions demandées restent à implémenter puis à recapturer.
